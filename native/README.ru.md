# Установка без Docker

[English](README.md) · Русский

Пробная установка всего Placitum на одну машину с Debian 13: процессы работают как юниты systemd,
компоненты ставятся пакетами .deb. Пакеты собираются из тех же образов, что строит `install.sh`.
Основная установка — по-прежнему `install.sh` в корне репозитория.

## Сборка и установка

Пакеты собираются на машине с Docker, где `./install.sh install` уже собрал образы:

```sh
sh native/build.sh        # пакеты из локальных образов в native/work/packages
```

Скопируйте пакеты и установщик на машину с Debian 13 в один каталог и запустите там:

```sh
scp -r native/work/packages native/install.sh native/check.mjs user@server:placitum/
ssh user@server 'cd placitum && sudo sh install.sh'
```

Каталог `packages/` должен лежать рядом с `install.sh`. Инфраструктура ставится из репозиториев:
Debian (PostgreSQL, Redis), nginx.org (та версия nginx, против которой собран модуль), ClickHouse и
NodeSource. В конце установщик покажет адрес панели и пароль `admin`.

| Команда | Что делает |
| --- | --- |
| `sudo sh install.sh` | ставит; спрашивает то, чего ещё нет в ответах |
| `sudo sh install.sh --reconfigure` | переспрашивает всё; текущие ответы становятся умолчаниями |
| `sudo sh install.sh --defaults` | ставит без вопросов, для недостающих ответов берёт умолчания |
| `sudo sh install.sh status` | показывает, что запущено |
| `sudo sh install.sh check` | проверяет чистую установку глазами пользователя |

## Файлы

| Файл | Что делает |
| --- | --- |
| `build.sh` | собирает 19 пакетов из локальных образов: бинарники, каталоги `/app`, юниты с окружением образа; `work/packages/MANIFEST` — какой коммит в каком образе |
| `install.sh` | вопросы, репозитории, пакеты, секреты, конфиги, база, схема, процессы, панель, рассылка |
| `check.mjs` | проверка чистой установки для systemd и адресов 127.0.0.1; её запускает `install.sh check` |
| `pkg/` | то, что едет в пакеты помимо образов: `app-sync`, шаг узла `tune.mjs`, сборка шага панели |

## Вопросы установщика

Ответы пишутся в `/etc/placitum/placitum.conf`. Повторный запуск берёт их из файла и ничего не
спрашивает. Пароль `admin` в ответах не хранится: без терминала он берётся из `PLC_PANEL_PASSWORD`,
если пусто — генерируется и показывается один раз.

| Ответ | По умолчанию | Что задаёт |
| --- | --- | --- |
| `PLC_NODE_ID` | `edge-01` | имя узла в панели и в аудите |
| `PLC_HTTP_PORT` | `80` | порт трафика; порты, занятые самим Placitum, не принимаются |
| `PLC_PANEL_BIND` | `127.0.0.1` | адрес панели: loopback, `0.0.0.0` или адрес интерфейса машины |
| `PLC_NGINX_WORKERS` | `auto` | воркеры nginx, настройка узла в панели |
| `PLC_COPIES_<ИНСПЕКТОР>` | `1` | копий каждого инспектора: `ip`, `modsec`, `json`, `counter`, `action`, `rewrite`, `cookie`, `auth`, `captcha` |
| `PLC_REDIS_EXCHANGE_MB`, `PLC_REDIS_INTERNAL_MB` | `512`, `256` | пределы памяти буфера и внутреннего Redis |

Копия инспектора — экземпляр шаблона `placitum-<инспектор>@<n>`. Если число уменьшили, лишние
экземпляры установщик останавливает и снимает.

## Что куда ставится

| Что | Откуда | Куда |
| --- | --- | --- |
| nginx 1.28.0 | nginx.org, закреплён `apt-mark hold` | модуль собран против этой версии: `/usr/lib/nginx/modules` |
| бинарники Placitum | пакеты `placitum-*` | `/usr/lib/placitum/bin`, не в PATH: `ip` и `json` спорили бы с системными |
| каталоги `/app` образов | пакеты `placitum-*` | `/usr/share/placitum/<компонент>`; у каждого процесса своя копия в `/var/lib/placitum/<процесс>/app`, данные рядом, в `data` |
| контроллер | `placitum-controller` | `/usr/lib/placitum/controller`, Node.js 22 из NodeSource |
| NATS 2.12, MinIO, клиенты `nats` и `mc` | бинарники из образов `compose/infra.yml` | `/usr/lib/placitum/bin` |
| PostgreSQL, Redis | Debian 13 | Redis — два своих экземпляра, `placitum-redis@exchange` и `@internal`; юнит пакета выключен |
| ClickHouse 24.8 | репозиторий ClickHouse | пользователь `waf` в `users.d/placitum.xml`, журнал — в journald |
| ответы, окружение, секреты | `install.sh` | `/etc/placitum`: `placitum.conf`, `env/*.env`, `secrets/` |

Перед стартом `app-sync` даёт процессу свою копию каталога, как слой образа контейнеру: инспекторы
пишут в свои каталоги. Если метка сборки `.build` разошлась с пакетом, копия пересоздаётся.

Окружение юнита `build.sh` берёт из окружения образа: пути `/app` и `/var/lib/waf/<x>` переезжают в
каталоги процесса. Адреса, порты и реквизиты не переносятся: их пишет `install.sh` в
`/etc/placitum/env`, и этот файл главнее юнита.

## Порты на машине

| Порт | Кто | Адрес |
| --- | --- | --- |
| 80, 8081, 8079 | nginx: трафик, панель, заглушка до первого поколения | порты трафика и панели — из ответов |
| 8080 | контроллер, API без входа | 127.0.0.1 (`CONTROLLER_HOST`) |
| 8091 | поиск | 127.0.0.1 (`SEARCH_HOST`) |
| 8085, 8086 | формы входа и капчи | 127.0.0.1 |
| 8092, 50051, 8093, 8094 | geo, crypto, keeper | 127.0.0.1 |
| 4222, 8222 | NATS | 127.0.0.1 |
| 6379, 6380 | Redis: буфер и внутренний | 127.0.0.1 |
| 5432, 8123, 9000 | PostgreSQL, ClickHouse | localhost |
| 9100, 9101 | MinIO: API и консоль | 127.0.0.1 |

У контроллера и поиска нет входа, поэтому установщик привязывает их к 127.0.0.1
(`CONTROLLER_HOST`, `SEARCH_HOST` в их файлах окружения).

## Чем отличается от установки в Docker

- Пулы панели — на 127.0.0.1 без resolve. Имён контейнеров нет, resolver Docker не
  настраивается: шаг панели `bootstrap/panel.mjs` берёт адреса из переменных `PANEL_*`.
- Встроенный порт `http-8080` становится `PLC_HTTP_PORT`. В контейнере узел слушает 8080, а на
  одной машине 8080 занят контроллером (`pkg/tune.mjs`).
- Роль `waf` не суперпользователь PostgreSQL. Расширение pgcrypto
  доверенное, его ставит сам владелец базы; поставленное заранее от postgres ломает схему на
  `COMMENT ON EXTENSION`.
- Пин отпечатка ключа пишется при установке. Панель читает его из
  `/usr/lib/placitum/controller/ux/dist/contour-pin.json`; отпечаток машины туда пишет root,
  процесс контроллера свои файлы не пишет.
- У каждого юнита свой `WAF_LOG_WRITER`. Без контейнеров у всех процессов в журналах было бы
  одно имя машины.

## Ограничения

Вопроса о прокси в установщике пока нет; HAProxy перед nginx появится вместе с его поддержкой. `vlai`
в пакеты не собирается. Повторный `install.sh` ставит новые пакеты, но работающие процессы не
перезапускает. TLS на узле и на панели нет, и готовый образ машины этот установщик не собирает. MinIO
с октября 2025 выходит только в исходниках, а в феврале 2026 архивирован, так что ему нужна замена.
