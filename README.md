# core — фундамент и установка Placitum

Один репозиторий, с которого начинается установка: инфраструктура, её конфигурация, бутстрап и
файл, по которому поднимается весь контур. Компоненты живут своими репозиториями, а `core`
знает, откуда их взять и в каком порядке запустить.

Готовых образов никто не раздаёт — **установка собирает их у себя из исходников**. Реестр
появится позже и поменяет только источник образа.

Соседние документы живут в платформе: раскладка на слои и открытые вопросы — `docs/repos.md`,
производство образов — `docs/delivery.md`, адреса инфраструктуры и умолчания — `docs/env.md`.
Ссылки на них появятся здесь, когда платформа станет публичной.

## Быстрый старт

```sh
git clone https://github.com/exemt/placitum-core.git
cd placitum-core
./install.sh check        # чем и куда ставим: docker, compose, место, источники
./install.sh install      # окружение, секреты, инфраструктура, компоненты
```

`install.sh` идёт по шагам и на каждом останавливается с внятной причиной:

| Шаг | Что делает |
| --- | --- |
| `check` | docker и compose (нужен 2.20+ — установка держится на `include`), openssl, место на диске, файл источников |
| окружение | заводит `.env` из `.env.example`, если его нет |
| секреты | выпускает ключ контура (RSA-4096) и реквизиты архива, прописывает отпечаток ключа в `.env` |
| инфраструктура | поднимает NATS, Postgres, ClickHouse, оба Redis и MinIO, заводит потоки JetStream |
| схема | накатывает схему базы контроллера — **накатчика пока нет**, шаг предупреждает и идёт дальше ([migrate/README.md](migrate/README.md)) |
| компоненты | собирает образы из исходников и поднимает контур |
| `status` | что поднято, адреса панели и трафика |

## Состав

```
core/
├── install.sh             установщик: проверки, секреты, шаги, статус
├── sources.env            откуда брать исходники компонентов -- он же манифест версий
├── .env.example           окружение установки: порты, реквизиты, имя узла
├── compose/
│   ├── waf.yml            весь контур: include инфраструктуры плюс компоненты
│   ├── infra.yml          инфраструктура и её бутстрап
│   └── empty/             пустой каталог: умолчание для монтирований установки
├── config/
│   ├── nats/              nats-server.conf: JetStream, лимиты, мониторинг
│   ├── clickhouse/        logger.xml, system-logs.xml
│   ├── minio/             lifecycle.json и lifecycle.sh: правила удаления бакетов
│   ├── edge/              agent.conf и node.conf узла защиты
│   └── geo/               каталоги страны и ASN, пустые до загрузки оператором
├── bootstrap/
│   ├── streams.sh         потоки JetStream WAF_AUDIT и WAF_LOG
│   └── secrets.sh         ключ контура и реквизиты архива
├── migrate/               накатчик схемы Postgres -- его ещё нет
└── secrets/               выпущенные ключи; в git не лежат
```

## Источники и версии

`sources.env` — единственное место, где написано, откуда берётся каждый компонент:

```
PLC_SRC_LOGGER=https://github.com/exemt/placitum-logger.git#main
PLC_SRC_ACTION=https://github.com/exemt/placitum-action.git#main
```

Значение — контекст сборки docker: git-URL с веткой или тегом либо путь на диске. Отсюда два
режима:

- **`#main`** — пилот и стенд: всегда свежее, воспроизводимости нет.
- **`#v1.2.0`** — промышленная установка: зафиксированный набор. Тогда `sources.env` и есть
  версия установки целиком, и её можно вернуть назад одной правкой.

Пока компоненты лежат в монорепозитории, а не в своих репозиториях, источники подменяются
файлом:

```sh
cat > sources.local.env <<'EOF'
PLC_SRC_LOGGER=../../logger
PLC_SRC_ACTION=../../inspectors/action
EOF
./install.sh install --sources sources.local.env
```

Пути в нём считаются от `compose/` — это каталог проекта для compose.

## Что поднимается

Инфраструктура (`compose/infra.yml`):

| Сервис | Порты | Роль |
| --- | --- | --- |
| `nats` | 4222, 8222 | шина: опрос инспекторов, аудит, журнал, доставка конфигурации, наборы |
| `nats-box` | — | бутстрап потоков при старте, дальше живёт для `exec` |
| `postgres` | 5432 | конфигурация контроллера |
| `clickhouse` | 8123, 9000 | события безопасности и журнал процессов |
| `redis` | 6379 | обменник: тело, заголовки и строка запроса на время волны |
| `redis-internal` | 6380 | внутренний: блобы поколений, корзины, нонсы, состояние keeper |
| `minio` | 9002, 9001 | архив тел, заголовков и строки запроса |
| `minio-mc` | — | правила удаления бакетов при старте, дальше под рукой |

Контур (`compose/waf.yml`): узел защиты (`edge` — nginx с модулем и агент в одном контейнере),
`controller` с панелью, `logger` и `search`, `crypto`, `geo`, `keeper`, шесть инспекторов
(`ip`, `modsec`, `json`, `counter`, `action`, `rewrite`) и три сайдкара наблюдения.

Инспекторы не слушают сеть — они подписчики очереди шины. Ни адреса, ни порта им не нужно, и
добавление копии не трогает ни узел, ни конфигурацию.

Чего в этом файле пока нет: калитка и капча (им нужны свои ключи подписи и HTTP-сайдкары),
`cookie`, `vlai` с моделью, балансировщик перед несколькими узлами. Это следующий слой.

## Потоки JetStream

`bootstrap/streams.sh` заводит `WAF_AUDIT` (`waf.audit.>`, 24 ч, 256 МБ) и `WAF_LOG`
(`waf.log.>`, 24 ч, 128 МБ), оба с `discard old`. Скрипт идемпотентен: существующий поток не
трогает.

Это не украшение: потребители к потокам **подключаются** (`BindStream`), но не создают их —
логгер без `WAF_AUDIT` не стартует вовсе.

```sh
docker compose exec -T nats-box sh /etc/waf/streams.sh
docker compose exec -T nats-box nats stream ls
```

## Секреты

`bootstrap/secrets.sh` выпускает пару ключа контура (RSA-4096: приватный PKCS#8, публичный
SPKI) и реквизиты архива в формате AWS-профиля. Идемпотентно — существующие файлы не трогает.

Приватную половину видят только агент узла и `crypto`; публичную — контроллер. Отпечаток
(`sha256` по DER публичного ключа) зашивается в сборку панели: по нему браузер сверяет ключ,
который вернёт API. `--force` перевыпускает ключ и **обнуляет доверие контура** — сертификаты,
зашифрованные прежним, перестанут расшифровываться.

## Схемы баз

DDL объявляет владелец данных, а не `core`:

- **ClickHouse** накатывает логгер при старте — 35 миграций, отметки в `waf.schema_migrations`,
  блокировка против гонки реплик. Работает.
- **Postgres** не накатывает никто: 103 файла схемы контроллера применяются только на пустом
  томе. Установка это чувствует сразу — [migrate/README.md](migrate/README.md).

## Границы: что сюда не едет

- **Код компонентов.** Инспекторы, сервисы, агенты, контроллер и модуль — свои репозитории.
- **Профили и политика.** Их ведёт панель и раскатывает контроллер; в образах лежат умолчания.
- **Стенд разработки.** `deploy/` в монорепозитории — отдельная установка со своими тремя
  узлами, тестовым приложением и генератором нагрузки; инфраструктуру он берёт отсюда же через
  `include`.

## Как устроено подключение инфраструктуры

```yaml
include:
  - path: infra.yml
```

Пути внутри включённого файла считаются **от его каталога** — ради этого выбран `include`, а не
цепочка `-f`.

Переопределить сервис из `include` нельзя: compose отвечает
`services.<имя> conflicts with imported resource`, и это касается даже одного добавленного
монтирования. Поэтому то немногое, что у установки своё, `infra.yml` принимает переменными:

| Переменная | Умолчание | Зачем |
| --- | --- | --- |
| `WAF_PG_INITDB` | `./empty` | каталог, который postgres прочитает на пустом томе |
| `WAF_NATS_BOX_MOUNT` | `./empty` | каталог установки в `/t` у `nats-box` |
| `CLICKHOUSE_LOG_LEVEL` | `warning` | уровень журнала сервера ClickHouse |
