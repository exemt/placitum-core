# Установка без Docker

Первая итерация самой простой раскладки: весь контур на одной машине с Debian 13, процессы —
юниты systemd, компоненты — пакеты .deb. Пакеты собираются из тех же образов, что строит
`install.sh`, а шаг панели — заменами из `bootstrap/panel.mjs`: своими у установки без Docker
остаются только адреса. Основная установка — по-прежнему `install.sh` в корне репозитория.

## Как поднять

Команды — из корня репозитория, на машине с Docker, где `install.sh` уже собрал образы контура.
Для пробной машины хосту нужны `qemu-system-x86`, `qemu-utils`, `cloud-image-utils` и членство
в группе `kvm`; облачный образ Debian и ключ ssh `vm.sh` заведёт сам.

```sh
sh native/build.sh                                   # пакеты из локальных образов -> native/work/packages
sh native/vm.sh up && sh native/vm.sh wait           # Debian 13 под QEMU/KVM
sh native/vm.sh copy native/work/packages native/install.sh native/check.mjs placitum
sh native/vm.sh ssh 'cd placitum && sudo sh install.sh'      # спросит, что и сколько ставить
sh native/vm.sh ssh 'sudo node placitum/check.mjs'           # чистая установка глазами пользователя
```

Панель с хоста — `http://127.0.0.1:18081` (в машине 8081), вход `admin` с паролем из итога
установки. Панель будет видна с хоста, если на вопрос об адресе панели ответить `0.0.0.0`: порт
QEMU приходит на адрес машины, а не на её loopback. `sh native/vm.sh destroy` сносит диск, и
следующий `up` даёт чистую машину.

Панель в локальной сети — строка `VM_PANEL_PUBLIC=<адрес хоста>:9000` в `native/work/vm/vm.env`
и `sh native/vm.sh restart`: порт слушает сам QEMU, без прокси и правил на хосте. Панель там
идёт по HTTP, пароль в сети — открытым текстом.

## Защищаемое приложение

Витрина `shop` — тестовое приложение платформы, образ `placitum/testapp` собирает рабочее место
разработки. На хосте она живёт отдельным контейнером со своим именем и портом:

```sh
sh native/testapp.sh up       # native-testapp, 127.0.0.1:18090 на хосте
```

Машина видит хост по адресу шлюза QEMU: апстрим в панели машины — `10.0.2.2:18090`.

## Что в каталоге

| `build.sh` | 19 пакетов из локальных образов: бинарники, каталоги `/app`, юниты с окружением образа; `work/packages/MANIFEST` — какой коммит в каком образе |
| `install.sh` | вопросы, репозитории, пакеты, секреты, конфиги, база, схема, процессы, панель, рассылка |
| `check.mjs` | мерка чистой установки для systemd и адресов 127.0.0.1 |
| `vm.sh` | пробная машина под QEMU/KVM без libvirt: сеть QEMU хост не трогает, порты — на 127.0.0.1 хоста и, если попросить, панель на его внешнем адресе |
| `testapp.sh` | витрина `shop` на хосте — приложение, которое защищает машина |
| `pkg/` | то, что едет в пакеты помимо образов: `app-sync`, шаг узла `tune.mjs`, сборка шага панели |
| `work/` | облачный образ Debian, диск машины, пакеты, ключ ssh; в git не идёт |

## Вопросы установщика

Ответы пишутся в `/etc/placitum/placitum.conf`. Повторный запуск берёт их из файла и ничего не
спрашивает, `--reconfigure` переспрашивает всё, `--defaults` ставит без вопросов. Пароль `admin`
в ответах не хранится: без терминала — `PLC_PANEL_PASSWORD`, пусто — генерируется и
показывается один раз.

| Ответ | Умолчание | Что |
| --- | --- | --- |
| `PLC_NODE_ID` | `edge-01` | имя узла в панели и в аудите |
| `PLC_HTTP_PORT` | `80` | порт трафика; занятые контуром порты не принимаются |
| `PLC_PANEL_BIND` | `127.0.0.1` | адрес панели: loopback, `0.0.0.0` или адрес интерфейса машины |
| `PLC_NGINX_WORKERS` | `auto` | воркеров nginx, настройка узла в панели |
| `PLC_COPIES_<ИНСПЕКТОР>` | `1` | копий каждого инспектора: `ip`, `modsec`, `json`, `counter`, `action`, `rewrite`, `cookie`, `auth`, `captcha` |
| `PLC_REDIS_EXCHANGE_MB`, `PLC_REDIS_INTERNAL_MB` | `512`, `256` | потолки памяти обменника и внутреннего Redis |

Копия инспектора — экземпляр шаблона `placitum-<инспектор>@<n>`. Уменьшили число — лишние
экземпляры установщик останавливает и снимает.

## Что куда ставится

| Что | Откуда | Где |
| --- | --- | --- |
| nginx 1.28.0 | nginx.org, закреплён `apt-mark hold` | модуль собран против этой версии: `/usr/lib/nginx/modules` |
| наши бинарники | пакеты `placitum-*` | `/usr/lib/placitum/bin`, не в PATH: `ip` и `json` спорили бы с системными |
| каталоги `/app` образов | пакеты `placitum-*` | `/usr/share/placitum/<компонент>`; у процесса своя копия в `/var/lib/placitum/<процесс>/app`, данные — рядом, в `data` |
| контроллер | `placitum-controller` | `/usr/lib/placitum/controller`, Node.js 22 из NodeSource |
| NATS 2.12, MinIO, клиенты `nats` и `mc` | бинарники из образов `compose/infra.yml` | `/usr/lib/placitum/bin` |
| PostgreSQL, Redis | Debian 13 | Redis — два своих экземпляра, `placitum-redis@exchange` и `@internal`; юнит пакета выключен |
| ClickHouse 24.8 | репозиторий ClickHouse | пользователь `waf` в `users.d/placitum.xml`, журнал — в journald |
| ответы, окружение, секреты | `install.sh` | `/etc/placitum`: `placitum.conf`, `env/*.env`, `secrets/` |

Свою копию каталога процессу даёт `app-sync` перед стартом, как слой образа контейнеру:
инспекторы пишут в свои каталоги. Метка сборки `.build` разошлась с пакетом — копия
пересоздаётся.

Окружение юнита `build.sh` берёт из окружения образа: пути `/app` и `/var/lib/waf/<x>` переезжают
в каталоги процесса. Адреса, порты и реквизиты не переносятся — их пишет `install.sh` в
`/etc/placitum/env`, и файл окружения главнее строк юнита.

## Порты внутри машины

| Порт | Кто | Адрес |
| --- | --- | --- |
| 80, 8081, 8079 | nginx: трафик, панель, заглушка до первого поколения | порт трафика и панели — из ответов |
| 8080 | контроллер, API без калитки | **все адреса**: адрес не настраивается |
| 8091 | поиск | **все адреса**: настраивается только порт |
| 8085, 8086 | формы входа и капчи | 127.0.0.1 |
| 8092, 50051, 8093, 8094 | geo, crypto, keeper | 127.0.0.1 |
| 4222, 8222 | NATS | 127.0.0.1 |
| 6379, 6380 | Redis: обменник и внутренний | 127.0.0.1 |
| 5432, 8123, 9000 | PostgreSQL, ClickHouse | localhost |
| 9100, 9101 | MinIO: API и консоль | 127.0.0.1 |

В пробной машине контроллер и поиск снаружи не видны: QEMU пробрасывает только 22, 80, 443 и
8081. На настоящей машине перед ними нужен фаервол, пока у них нет настройки адреса.

## Чем отличается от установки в Docker

- **Пулы панели — 127.0.0.1 без resolve.** Имён контейнеров нет, resolver Docker не печатается.
  Шаг панели собирается из `bootstrap/panel.mjs` заменами (`pkg/patch-panel.mjs`); замена, не
  нашедшая своё место ровно один раз, роняет сборку.
- **Порт поставки `http-8080` становится `PLC_HTTP_PORT`.** В контейнере узел слушает 8080, на
  одной машине 8080 занят контроллером (`pkg/tune.mjs`).
- **waf не суперпользователь PostgreSQL.** В образе postgres он им был. Расширение схемы
  pgcrypto доверенное, его ставит сам владелец базы. Поставленное заранее от postgres ломает
  baseline на `COMMENT ON EXTENSION`.
- **Пин отпечатка ключа контура подменяется при установке.** Он зашит в сборку панели
  (`VITE_CONTOUR_FINGERPRINT`), а ключ у машины свой. Прежний пин лежит в
  `/usr/lib/placitum/controller/PIN`; подменяет root, процесс контроллера свои файлы не пишет.
- **Имя в журналах — `WAF_LOG_WRITER` у каждого юнита.** Без контейнера имя машины у всех одно.

## Проверено 14.09.2026

С нуля: `build.sh`, новая машина (4 ядра, 6 ГБ, 40 ГБ), `install.sh --defaults` с одним заранее
записанным ответом `PLC_PANEL_BIND=0.0.0.0`.

- Установка — 2 мин 47 с, из них почти две минуты — apt update и PostgreSQL с Redis.
- `check.mjs` — 21 из 21: один сервер `panel`, пулы на 127.0.0.1, каналы сошлись (без получателя —
  haproxy и vlai), флот из 16 участников up, 25 юнитов, упавших нет.
- Вход `admin` через калитку с хоста: форма с CSRF, 303, `/api/spaces` с сессией — 200.
- Стоят nginx 1.28.0-1~trixie, PostgreSQL 17.11, Redis 8.0.2, ClickHouse 24.8.14.39, Node.js 22.23.2.
- Память машины после установки — 1,5 ГБ из 6; больше всех ClickHouse (около 0,5 ГБ) и MinIO
  (около 0,3 ГБ), контроллер — 0,13 ГБ, остальные процессы — десятки мегабайт.
- `install.sh --reconfigure` через терминал, воркеров 2 и копий modsec 2: у узла
  `worker_processes 2`, два экземпляра `placitum-modsec@`, флот из 17 участников, мерка сошлась,
  пароль admin прежний.
- Перезагрузка машины: контур поднимается сам — 26 процессов, упавших нет, мерка сошлась.
- Панель на внешнем адресе хоста через `VM_PANEL_PUBLIC`, витрина на хосте видна из машины по
  `10.0.2.2:18090`.

При старте Go-процессы пишут одно предупреждение `log levels watch … bucket not found`: KV уровней
журнала контроллер ещё не завёл. Та же строка есть у контейнеров установки в Docker.

## Чего пока нет

- Вопроса о прокси: HAProxy перед nginx появится в установщике вместе с поддержкой.
- Фаервола для контроллера и поиска.
- vlai.
- Обновления: повторный `install.sh` ставит новые пакеты, но работающие процессы не перезапускает.
- TLS на узле и на панели.
- Готового образа машины из этого установщика.
- Замены MinIO: с октября 2025 он выходит только в исходниках, архивирован в феврале 2026.
