# Placitum core

[English](README.md) · Русский

Отсюда устанавливается Placitum, файрвол для веб-приложений и API.

В репозитории всё, что нужно для установки на свой сервер: скрипт `install.sh`, compose-файлы,
конфиги инфраструктуры и первичная настройка. Сами компоненты (узел на nginx, контроллер с
панелью, инспекторы) лежат в отдельных репозиториях. Установщик скачивает их исходники и
собирает образы прямо на вашей машине. Готовая виртуальная машина с собранными образами описана в
[image/README.ru.md](image/README.ru.md).

Подробная инструкция — в [INSTALL.ru.md](INSTALL.ru.md).

## Что нужно

- Linux, Docker 24+ и Docker Compose 2.20+
- не меньше 2 ядер и 4 ГБ памяти ([что это держит](image/README.ru.md#размер-машины)); 8 ядер и
  16 ГБ для большого трафика; с классификатором текста `vlai` ещё 4 ГБ
- 20 ГБ свободного места
- `openssl`
- интернет на время сборки: GitHub, Docker Hub, quay.io, proxy.golang.org, npm, PyPI

## Установка

```sh
git clone https://github.com/exemt/placitum-core.git
cd placitum-core
./install.sh check      # проверить машину, ничего не устанавливая
./install.sh install
```

В начале установщик спросит несколько настроек: адреса трафика, адрес панели, сеть для контейнеров,
нужны ли несколько узлов защиты за балансировщиком и подходят ли стандартный набор инспекторов и
стандартные память, копии и процессы; «нет» открывает вопросы за каждым. Порты спрашиваются, только
если на машине они уже заняты. Enter берёт значение в скобках. Установщик показывает план и
применяет его после подтверждения. Потом он спросит пароль для входа в панель под
именем `admin`. Можно просто нажать Enter: пароль сгенерируется и будет показан один раз ближе к
концу установки. В открытом виде он нигде не хранится. Если терминала нет, пароль передаётся в
переменной `PLC_PANEL_PASSWORD`, а настройки — в окружении, см. [INSTALL.ru.md](INSTALL.ru.md#установка).

Дальше всё идёт само: установщик пишет `.env` с новыми паролями баз, выпускает ключи, поднимает
базы и шину, собирает и запускает компоненты, настраивает панель. Первая сборка долгая, потому что
компилируется модуль nginx и собирается панель. Если какой-то шаг упадёт, установка
остановится и покажет конец журнала. Полный журнал пишется в `install.log`.

## После установки

В конце установщик покажет адреса. По умолчанию:

- панель: http://127.0.0.1:8080, вход `admin`
- трафик приложения: порты 80 и 443 на всех адресах машины
- API контроллера: http://127.0.0.1:8081

Панель открыта только с самой машины. С другой машины проще всего зайти через ssh-туннель:

```sh
ssh -L 8080:127.0.0.1:8080 user@server
```

После этого панель откроется у вас на http://127.0.0.1:8080.

Сразу после установки в панели есть только один сервер, сама панель. Как завести первый маршрут
и проверить, что трафик идёт через Placitum, написано в [INSTALL.ru.md](INSTALL.ru.md#после-установки).

Панель работает через API контроллера, и вы можете так же: справочник — в [API.ru.md](API.ru.md).

## Команды

| Команда | Что делает |
| --- | --- |
| `./install.sh check` | проверяет машину и настройки, ничего не меняя |
| `./install.sh install` | ставит всё по порядку; запускать можно повторно |
| `./install.sh reconfigure` | заново спрашивает настройки и применяет их |
| `./install.sh status` | показывает, что запущено, и адреса |
| `./install.sh panel-password` | меняет пароль `admin` и снимает блокировку входа |
| `./install.sh panel` | возвращает сервер и вход панели, если их удалили; остальные правки не трогает |
| `./install.sh infra` | поднимает только инфраструктуру |
| `./install.sh down` | останавливает всё, данные остаются |

Ключи: `--no-build` никогда не собирает образы и не предлагает то, для чего образа на машине нет,
`--sources <файл>` берёт исходники компонентов из другого файла, `--defaults` ничего не спрашивает
и берёт настройки из окружения или значения по умолчанию.

## Настройки

Настройки установки лежат в `.env`. При первом запуске он создаётся из `.env.example`, там же
описана каждая переменная. Чаще всего меняют эти:

| Переменная | По умолчанию | Что задаёт |
| --- | --- | --- |
| `PLC_TRAFFIC_BIND` | `0.0.0.0` | адреса трафика; `0.0.0.0` — все, или адреса этой машины через запятую |
| `PLC_HTTP_PORT`, `PLC_HTTPS_PORT` | `80`, `443` | порты для трафика приложения |
| `PLC_PANEL_BIND` | `127.0.0.1` | адрес машины, на котором открыта панель; `0.0.0.0` — все адреса |
| `PLC_PANEL_PORT` | `8080` | порт панели |
| `PLC_NODE_ID` | `edge-01` | имя узла в панели и журнале |
| `PLC_SUBNET` | свободная сеть | сеть для контейнеров; не должна пересекаться с сетями машины |
| `PLC_INFRA_PORTS` | `none` | `loopback` открывает базы, NATS и MinIO на 127.0.0.1, чтобы подключаться к ним с машины |
| `PLC_COOKIE_SECURE` | `off` | поставьте `on`, когда узел работает по HTTPS |
| `PLC_NODES` | `1` | узлов защиты на машине; больше одного — перед ними встаёт haproxy |
| `PLC_NGINX_WORKERS` | `auto` | процессов nginx на узел |
| `PLC_COPIES_<ИНСПЕКТОР>` | `1`, у vlai `0` | копий каждого инспектора; 0 выключает его |
| `PLC_REDIS_EXCHANGE_MB`, `PLC_REDIS_INTERNAL_MB` | по памяти машины | память двух Redis, МБ |

`./install.sh reconfigure` заново спрашивает настройки, показывает, что изменится, и применяет это к
работающей установке: узлы, инспекторы и процессы добавляются и убираются без потери данных.

## Откуда берутся компоненты

В `sources.env` на каждый компонент одна строка: адрес репозитория и ветка или тег.

```
PLC_SRC_CONTROLLER=https://github.com/exemt/placitum-controller.git#rc_1.0.2
```

Все компоненты берутся из ветки `rc_1.0.2` — кандидата в выпуск. Когда появятся выпуски, вместо ветки
можно будет указать тег, например `#v1.2.0`. Тогда версию всей установки задаёт один этот файл.

Чтобы собрать компонент из своей копии исходников, скопируйте `sources.env`, замените в копии
адрес на путь к каталогу и передайте файл установщику. Пути считаются от каталога `compose/`.

```sh
cp sources.env sources.local.env
./install.sh install --sources sources.local.env
```

## Безопасность

- API контроллера на `127.0.0.1:8081` работает без входа. Не открывайте его наружу и не ставьте
  перед ним прокси. Если нужен доступ с другой машины, используйте ssh-туннель.
- Docker публикует порты в обход UFW и других фаерволов на машине. Кому видна панель, решает
  только `PLC_PANEL_BIND`.
- Если панель доступна не только с самой машины, отдавайте её по HTTPS. Иначе пароль уходит по
  сети открытым текстом.
- Ключи установки лежат в `secrets/` и в git не попадают. Не запускайте
  `bootstrap/secrets.sh --force` без крайней нужды: он выпускает новый ключ, и сертификаты,
  загруженные через панель, перестанут расшифровываться.

## Что запускается

Инфраструктура (`compose/infra.yml`): NATS, PostgreSQL, ClickHouse, два Redis и MinIO. Снаружи
она не видна.

Сам Placitum (`compose/waf.yml`):

- `edge` — узел защиты, nginx с модулем Placitum. Через него идёт трафик приложения и
  открывается панель. Если `PLC_NODES` больше одного, рядом встают `edge-02` и дальше, а порты
  трафика занимает haproxy и раздаёт соединения всем узлам: в образе машины — прямо на машине, в
  остальных случаях — контейнером `balancer`.
- `controller` — API и панель управления.
- `logger` и `search` — запись событий и поиск по ним.
- Инспекторы, которые проверяют запросы: `ip`, `modsec`, `json`, `counter`, `action`, `rewrite`,
  `cookie`, `auth` (форма входа) и `captcha`. Каждый работает в стольких копиях, сколько задано;
  выключенного нет и в панели.
- Служебные `crypto`, `geo`, `keeper` и агенты, которые следят за Redis и MinIO.
- `vlai` — классификатор текста. По умолчанию выключен: он тяжёлый и при первом старте скачивает
  модель. Включает его `PLC_COPIES_VLAI=1`.

Схему баз сервисы ставят сами при старте: ClickHouse — `logger`, PostgreSQL — `controller`, на
пустой базе.

## Готовая виртуальная машина

`sh image/build.sh` собирает образ qcow2: Debian 13, Docker и все образы. При первом запуске машина
спрашивает настройки на консоли и устанавливается сама примерно за минуту; позже их меняет
`sudo placitum reconfigure`. Подробности и замеры нагрузки — в [image/README.ru.md](image/README.ru.md).

## Установка без Docker

Есть пробный вариант без Docker: всё на одной машине с Debian 13, сервисы устанавливаются пакетами .deb
и работают как юниты systemd. Пакеты пока собираются из образов, которые делает `install.sh`,
так что для сборки машина с Docker всё равно нужна. Подробности в
[native/README.ru.md](native/README.ru.md).

## Что в репозитории

```
install.sh      установщик
sources.env     откуда брать исходники компонентов
.env.example    шаблон настроек
compose/        compose-файлы: infra.yml — инфраструктура, waf.yml — всё вместе
config/         конфиги NATS, ClickHouse, MinIO и узла, каталоги для геоданных
bootstrap/      первичная настройка: ключи, потоки NATS, панель, применение настроек
native/         установка без Docker
image/          образ готовой виртуальной машины
secrets/        ключи установки, в git не попадают
```

## Чего пока нет

- Узлов на других машинах: несколько узлов работают только на одной машине.
- Обновления одной командой.
- Готовых образов в реестре: установщик собирает из исходников, собранные образы есть только в
  образе виртуальной машины.
- Манифестов для Kubernetes.
