# Установка

Что нужно машине, чем это называется, какими командами ставится и как убедиться, что контур
работает. Быстрый старт и состав репозитория — [README.md](README.md).

## Машина

| Что | Сколько |
| --- | --- |
| Docker | 24 или новее, с BuildKit |
| Docker Compose | 2.20 или новее: установка держится на `include` |
| Ядра и память | 8 ядер и 16 ГБ для контура без классификатора текста; с `vlai` — ещё 4 ГБ |
| Диск | 20 ГБ на образы, кеши сборки и данные; архив тел растёт со временем |
| Сеть | на время сборки — GitHub, Docker Hub, quay.io, proxy.golang.org, npm, PyPI |

Сборка идёт из исходников на этой же машине: готовых образов установка не качает. Первая сборка
занимает минуты — компилируется модуль nginx против исходников nginx, собирается панель. Это не
зависание.

Закрытый контур без сети — отдельный разговор: сборке нужны зеркала реестров и модулей, и они
подставляются через `GOPROXY` и переменные источников.

## Порядок

```sh
git clone -b develop https://github.com/exemt/placitum-core.git
cd placitum-core
./install.sh check
./install.sh install
```

`install` идёт по шагам и останавливается на первом отказе:

1. **Проверки** — Docker, Compose, `openssl`, место, файл источников.
2. **Окружение** — `.env` из `.env.example`, если его нет. Проверьте порты и реквизиты до
   следующего шага: потом их менять — пересоздавать контейнеры.
3. **Секреты** — ключ контура, реквизиты архива, четыре ключа подписи. Отпечаток ключа
   прописывается в `.env` и зашивается в панель на сборке.
4. **Инфраструктура** — NATS, Postgres, ClickHouse, оба Redis, MinIO; потоки JetStream и
   правила бакетов заводятся при старте.
5. **Схема** — накатчик из образа контроллера: сначала план, потом применение
   ([migrate/README.md](migrate/README.md)).
6. **Компоненты** — сборка образов из `sources.env` и запуск.
7. **Панель** — сервер `panel` на узле за калиткой `auth`, пользователь `admin` с паролем в
   `secrets/panel-admin.password` ([«Панель»](#панель)).
8. **Состояние** — таблица сервисов и адреса.

## Что задаёт установка

### `.env`

| Переменная | Умолчание | Что |
| --- | --- | --- |
| `COMPOSE_PROJECT_NAME` | `placitum` | имя проекта compose; одно на оба файла, иначе установщик не видит собственную инфраструктуру |
| `PLC_HTTP_PORT`, `PLC_HTTPS_PORT` | `80`, `443` | порты узла защиты на хосте |
| `PLC_PANEL_BIND` | `127.0.0.1` | адрес IPv4 машины, на котором узел отдаёт панель: `127.0.0.1` — только с неё, адрес внутреннего интерфейса — из его сети, `0.0.0.0` — со всех адресов |
| `PLC_PANEL_PORT` | `8081` | порт панели на этом адресе |
| `PLC_CONTROLLER_PORT` | `8080` | API контроллера без калитки, только на `127.0.0.1` |
| `PLC_NODE_ID` | `edge-01` | имя узла: в панели, в пульсе и в аудите |
| `PLC_COOKIE_SECURE` | `off` | `on` — куки калитки и капчи только по TLS; пока узел отвечает по HTTP, оставьте `off` |
| `POSTGRES_*`, `CLICKHOUSE_*`, `MINIO_ROOT_*` | `waf` / `waf` / `wafwafwaf` | реквизиты инфраструктуры; для внешних баз меняйте и адреса в `compose/waf.yml` |
| `NGINX_VERSION` | `1.28.0` | версия nginx для модуля и базового образа — одно число, менять только вместе |
| `VITE_CONTOUR_FINGERPRINT` | ставит `install.sh` | пин отпечатка ключа контура в панели |

### `sources.env`

Откуда берётся каждый компонент: git-URL с веткой или тегом либо путь на диске. Это и есть
версия установки. `#develop` — то, что разрабатывается; для промышленной установки ставятся теги.
Встроенных умолчаний у контекстов сборки нет: компонент без строки в `sources.env` не соберётся,
и это правильно — адрес, живущий в двух местах, расходится.

### Секреты

`secrets/` — в git не лежит. Ключ контура (RSA-4096) видят агент узла и `crypto`, публичную
половину — контроллер. Ключи подписи: `auth.hmac` и `auth-app.hmac` у калитки, `captcha.hmac` у
капчи, `cookie.hmac` у инспектора кук — друг с другом не делятся. Реквизиты архива — файлом в
формате AWS-профиля. Пароль `admin` панели — `panel-admin.password`: его выпускает шаг «Панель», в
список пользователей уезжает только bcrypt.

Перевыпуск ключа контура (`bootstrap/secrets.sh --force`) обнуляет доверие: сертификаты,
загруженные через панель, перестанут расшифровываться. Перевыпуск ключа подписи разлогинивает
всех, кого он подписывал, и ничего больше.

## Что поднимается

Восемь сервисов инфраструктуры и контур: узел защиты, контроллер с панелью, логгер и поиск,
`crypto`, `geo`, `keeper`, девять инспекторов (`ip`, `modsec`, `json`, `counter`, `action`,
`rewrite`, `cookie`, `auth` с формой входа, `captcha` с виджетом), три сайдкара наблюдения.
Классификатор текста `vlai` — за профилем compose:

```sh
docker compose --env-file .env --env-file sources.env -f compose/waf.yml --profile vlai up -d
```

Наружу смотрит только узел защиты: трафик (`PLC_HTTP_PORT`) и панель (`PLC_PANEL_BIND`,
`PLC_PANEL_PORT`). Контроллер опубликован лишь на `127.0.0.1`. Формы входа, виджет капчи, поиск и
`crypto` — внутри сети: в них ходят узел и контроллер.

## После установки

1. Панель на `http://127.0.0.1:8081` (или на адресе из `PLC_PANEL_BIND`): вход `admin`, пароль —
   в `secrets/panel-admin.password`. Внутри одно пространство `default`, каталог инспекторов,
   профили поставки и служебные серверы панели `panel` и `panel-backend`. Своих серверов и
   маршрутов нет — их заводит оператор.
2. Первый маршрут: сервер с привязкой к порту `http-8080` (он есть в поставке: узел слушает
   8080 внутри контейнера, снаружи это `PLC_HTTP_PORT`), путь, апстрим, инспекторы на
   маршруте; инспектор, которого зовёт маршрут, должен быть объявлен на пространстве
   (страница пространства → инспекторы), иначе сборка ответит `undeclared_inspector`.
   WAF на сервере или пути включается явно — строка `waf` в настройках маршрута: по
   умолчанию он выключен, и маршрут с инспекторами без неё модуль пропускает молча.
   «Разослать» — узел применяет поколение через `nginx -s reload` и отвечает в пульсе.
3. Запрос через узел: `curl -i http://<хост>/…` — ответ апстрима, а в панели через несколько
   секунд запись в журнале с вердиктом.
4. Каталог гео (страны и системы) заливается отдельно: выгрузка MaxMind лицензируется сама и в
   образы не едет; без неё правила по стране отвечают отказом с кодом, остальное работает.

## Проверка

```sh
./install.sh status                 # таблица сервисов
docker compose --env-file .env --env-file sources.env -f compose/waf.yml ps
curl -fsS http://127.0.0.1:8080/healthz          # контроллер
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8081/api/spaces   # панель без входа: 401
docker compose exec -T nats-box nats stream ls    # потоки WAF_AUDIT и WAF_LOG
```

Здоровый контур: все сервисы с healthcheck — `healthy`, у остальных в журнале кадр присутствия
каждые четыре секунды. Страница «Состояние» в панели показывает то же самое по-человечески.

## Панель

Людям панель отдаёт узел защиты, а не контроллер: сервер `panel` на порту 8081 контейнера, на нём
калитка `auth` — объявление `auth-panel`, источник и профиль `panel`, список пользователей
`panel_users`. Заводит это шаг «Панель» (`bootstrap/panel.mjs`) через API изнутри контейнера
контроллера. Повторный запуск — `./install.sh panel` — заводит только то, чего нет, и правок
оператора не трогает; `admin` появляется лишь в пустом списке.

В контроллер и форму входа узел ходит через свой внутренний сервер `panel-backend` на
`127.0.0.1:18081`, где адреса резолвятся на лету: лежащий контроллер — это 502 панели, а не отказ
всего поколения nginx на узле. Маршруты панели без вердикта калитки отказывают по любой причине,
в том числе когда лежит шина.

Где слушать — `PLC_PANEL_BIND`. Docker публикует порт на адрес, а не на интерфейс, и адрес обязан
быть на машине: иначе не поднимется узел, а с ним и трафик, — `./install.sh check` это проверяет.
Фаервол хоста здесь не граница: опубликованные порты docker проводит мимо UFW. Всё, что шире
loopback, стоит отдавать по TLS: иначе пароль идёт открытым текстом.

Контроллер без калитки — только `127.0.0.1:8080` (`PLC_CONTROLLER_PORT`): его API нужен
`install.sh`, e2e и аварийному входу, когда узел или калитка лежат. С другой машины — туннелем:

```sh
ssh -L 8080:127.0.0.1:8080 <хост>
```

Проксировать этот порт нельзя ничем: хостовый nginx или другой обратный прокси перед
`127.0.0.1:8080` снова выставит API наружу без входа. Прокси, если он нужен, ставят перед портом
панели (`PLC_PANEL_PORT`).

Без аварийного входа под рукой не трогать: калитку на путях `/` и `/agent_health_socket` сервера
`panel`, источник и профиль `panel`, последнего пользователя в `panel_users`. Калитка, снятая с
`/`, открывает панель без пароля.

## Порты инфраструктуры

По умолчанию Postgres, Redis, NATS, ClickHouse и MinIO снаружи не видны: они живут в сети
compose, и наружу смотрят только узел защиты и панель. Если нужно ходить в них с самой
машины (`psql`, `clickhouse-client`, консоль MinIO), поставьте `PLC_INFRA_PORTS=loopback` в
`.env` -- порты появятся на 127.0.0.1 -- и перезапустите `install.sh install`. На 0.0.0.0
они не публикуются намеренно.

## Версия сборки

`install.sh` берёт версию из тега core (без тега — `dev`) и ревизию из его коммита и передаёт
в каждую сборку. Их видно в метках образов, в строке `build` при старте каждого процесса
(`docker compose logs keeper | grep build`) и в кадре присутствия — на странице состояния.
Задать руками: `PLC_VERSION` и `PLC_REVISION` в `.env`.

## Обновление

Сборка новых образов и перезапуск по порядку: инфраструктура — инспекторы — контроллер — узел.
Новую схему контроллер накатывает сам при старте; посмотреть заранее, что применится, —
`./install.sh migrate` с `--check` внутри. Команды одной строкой для всего обновления пока нет —
см. «Чего ещё нет» в README.

## Грабли

- **Порты 80 и 443 заняты** другим сервисом машины — установка упадёт на узле. Переставьте
  `PLC_HTTP_PORT` и `PLC_HTTPS_PORT` до `install`.
- **Имя узла в двух местах**: `PLC_NODE_ID` в `.env` и `waf_node_id` в `config/edge/node.conf`.
  `install.sh` держит их вместе; правите руками — правьте оба.
- **Сменили ключ контура — пересоберите контроллер**: отпечаток зашит в панель на сборке.
- **`COMPOSE_PROJECT_NAME` не менять на ходу**: новое имя — новый проект, старые контейнеры и
  тома остаются под старым.
- **Windows-хост (Docker Desktop)**: сборщик bake не понимает git-адреса источников на Windows
  (`failed to evaluate path "https://…git#develop"`). Установка рассчитана на Linux; на
  Windows перед `install` поставьте `COMPOSE_BAKE=false` в окружении.
- **Секрет правили руками, и сервис лёг с `permission denied`**: процессы в образах работают от
  своих пользователей и читают файл секрета через монтирование как есть. Файлы в `secrets/` —
  `0644`, закрывает их каталог `0700`; `sh bootstrap/secrets.sh` выставит режимы заново, ничего
  не перевыпуская.
